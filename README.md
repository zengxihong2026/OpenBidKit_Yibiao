## 🧮 Token 消耗优化

针对长篇技术标生成过程中“输入上下文重复注入”导致 Token 快速增长的问题，当前代码已开始进行分阶段优化。重点不是单纯压缩模型输出，而是减少重复输入、缩小无关上下文和降低重复审计。

当前已落地：

- **TokenUsageLedger**：开发者模式下按请求记录 input / output / total / cached / reasoning Token，并按招标解析、目录、全局事实、正文编排、正文生成、字数调整、一致性审计等阶段聚合。
- **正文批量编排**：正文编排默认按最多 **40 个叶子小节/批次**处理，减少每个小节重复发送相同的项目概述、招标关键信息和知识库索引。
- **正文 Context Pack**：项目概述、全局事实和知识库正文素材设置上下文预算；单小节知识库正文素材默认最多 **3 条**，并限制单条及总字符量。
- **TenderContextRetriever**：正文生成不再把整份招标文件重复注入每个章节，而是根据当前章节标题与描述，从招标原文中检索最相关的少量片段后再注入模型。
- **风险驱动一致性审计**：超过 20 个正文小节时，默认优先审计高风险小节，并保留少量普通小节作为抽样；单小节重新生成会自动保持完整审计。
- **计划版本控制**：Token 优化后的正文编排计划使用新的版本号，避免历史编排结果绕过新的上下文约束。
- **Step02 关键解析合并**：项目概述、技术要求、项目信息、甲方信息、交付与服务要求等高频基础解析项在满足条件时合并为一次模型请求，共享同一份招标上下文。
- **Step02 可选解析分组**：其余资格/符合性、响应/废标、关键节点、评标、合同、代理机构、采购清单等解析项按业务域合并为少量批次，避免每个解析项重复发送同一招标上下文。
- **解析任务局部检索**：大型招标文件不再让每个 Step02 任务都完整读取全文，而是按任务语义检索高相关片段，并复用同一份本地检索索引。
- **TenderKnowledge**：把评分、合规、资格、响应、交付、合同和技术参数整理成可复用的结构化招标知识快照，正文和全局事实阶段优先消费高信号摘要。
- **Agent 原文分片**：原方案、招标文件、目录 Agent 等长材料改为“索引 + 分片按需读取”，降低 Agent 自动读取整个超长文件的概率。
- **原方案高置信自动归属**：原方案段落与目录标题高度确定匹配时，直接本地归属并跳过模型映射。
- **Agent 一致性风险筛选**：Agent 全文一致性修复沿用风险筛选，不再默认把全部成功小节一次性送入 Agent 工作集。
- **配图规划上下文压缩**：图片规划使用小节预览和正文索引，只有已选候选才读取完整正文；图片生成参考正文也设置总字符预算。
- **重复上下文诊断**：Token Ledger 增加按 context hash 聚合的重复上下文排行，方便继续定位最耗 Token 的重复请求。
- **正文批次进一步扩大**：正文编排默认批次从 10 调整到 **20 个叶子小节**，在控制单次输出规模的同时减少重复上下文请求次数。
- **提示词瘦身**：正文生成、字数调整、一致性审计、原方案覆盖审计等高频请求的固定指令进一步压缩；JSON 修复输入也限制最大长度。
- **相关性事实裁剪**：一致性审计会按当前章节内容从全局事实中优先提取相关变量，而不是每个审计组都发送完整事实集合。
- **敏感行审计**：一致性审计正文优先保留参数、人员、周期、验收、质保、合同、安全等事实敏感行，减少大段无关自然语言进入审计上下文。
- **结构化招标知识按章节裁剪**：正文编排批次不再固定发送完整知识快照，而是根据本批次小节标题和描述进一步裁剪到约 2800 字符预算。
- **知识库零相关条目抑制**：正文编排优先只提供与当前小节有关键词关联的知识库轻量条目，无相关命中时仅保留少量兜底条目。
- **原方案映射预览化**：普通原方案映射请求使用标题路径 + 受限正文预览；完整原文保留在 Agent 分片工作区，避免把数万字原文直接重复发送给映射模型。
- **长招标解析兜底预算化**：局部检索不足时也不会重新发送完整招标文件，而是退化为受预算限制的压缩上下文。
- **通用请求去重**：AI Service 在统一请求出口移除同一请求中任意位置完全重复的文本消息，并针对各阶段设置输出 Token 上限，减少异常路径和过量输出。
- **正文批量生成**：普通正文默认按 **3 个小节/批次**合并生成，复用共享系统指令和公共上下文；批量失败自动回退逐节生成。
- **字数与一致性局部窗口**：超长正文的字数调整、一致性修复和原方案覆盖审计优先使用相关段落/事实敏感行窗口，仍使用原文精确 patch 回写。
- **配图 Agent 阈值优化**：较长的 HTML 配图参考正文改为文件式 Agent 输入，避免将大段正文直接塞进普通请求。
- **无匹配检索收缩**：招标原文检索无明确匹配时不再回退发送多段无关原文，只保留极少量兜底上下文。
- **统一 Token Budget Policy**：阶段输出上限抽到独立策略模块，普通文本请求和 Agent Chat 请求共用同一套阶段预算，可按 economy / balanced / quality 档位缩放。
- **Agent 纳入统一预算链路**：Pi Agent 通过本地 AI Proxy 将 workflow stage / task_id 传入统一 AI 出口，使 Agent 请求也能套用阶段输出上限并进入 Token Ledger。
- **Agent Token Ledger 归属**：Ledger 增加 task_id、source_hash 和 output budget / over-budget 信息，便于把普通请求与 Agent 请求放在同一账本分析。
- **招标检索证据窗口化**：检索命中后优先截取命中位置附近的局部证据窗口，而不是直接把整个长段落交给模型；完全无命中时返回空结果，不再默认发送第一段原文。
- **Step02 无结果去重**：招标解析任务已经得到“整项无结果”后，不再用同一检索上下文重复提交第二次相同请求。
- **知识库零命中清零**：正文编排阶段没有相关知识库命中时直接不注入历史案例，避免无关素材占用上下文。
- **正文批量共享公共上下文**：3 小节批量生成时，项目概述和本次重新生成要求改为整个批次只发送一次，单节仅保留自己的招标片段、事实变量和参考素材。
- **目录确定性短路**：目录结构、叶子数量和评分映射均通过宿主程序确定性检查时，直接跳过额外 Agent 终审，只有存在疑点时才进入语义审核。

这些优化以“减少重复输入”为第一原则，同时保留原有恢复、重试和局部修复机制。实际 Token 消耗仍取决于模型、缓存命中、输出长度、知识库内容以及是否启用一致性/原方案扩写等功能。

开发者模式下可以通过 Token 统计与 Ledger 接口查看不同阶段的实际消耗，再据此继续调整批量大小、上下文预算和审计策略。

## 🛠️ 技术架构

- **桌面端**：Electron Main / Preload 提供本地能力，Renderer 通过 `window.yibiao` 调用
- **界面层**：Vite + React + TypeScript，使用全局 CSS 和 Radix UI
- **数据与任务**：配置保存在本地文件，业务状态存入 SQLite；耗时任务在 Main 后台运行并支持恢复
- **AI 与 Agent**：AI Service 统一管理模型请求，Pi Agent 使用独立 Runtime / Session 执行智能体任务
- **文档与在线服务**：支持本地或 MinerU 解析、Open XML 和本地图片渲染；Cloudflare Worker 提供公告、资源、插件、模型信息、许可证及统计服务
